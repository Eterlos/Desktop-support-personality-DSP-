# Автопроверка файлов репозитория

Проверка `Repository audit` запускается на push, pull request и вручную из Actions.
Это проверка по правилам, без LLM, API-ключей и автоматического удаления файлов.
Приложение не собирается и чужие компоненты не проверяются на функциональность.

## Что отмечается

- Любой файл больше 10 МиБ (10 485 760 байт).
- Модели: `.gguf`, `.onnx`, `.safetensors`, `.pt`, `.pth`, `.ckpt`, `.h5`, `.tflite`.
- Бинарные библиотеки, установщики и архивы: список в `.repo-audit.json`.
- Сборочные и локальные папки: `bin`, `obj`, `node_modules`, `.vs`, `TestResults`,
  а также корневые `data`, `models`, `.local`, `artifacts`, `publish`, `coverage`.

Расширения и имена служебных папок проверяются без учёта регистра.
Исходники `.cs`, `.xaml`, `.csproj`, `.sln` и обычные документы разрешены,
пока не превышен лимит. Зависимости NuGet описываются в `.csproj`;
скачанные DLL обычно не нужны в Git. Нужность отдельной DLL решает команда.
Проверка строже `.gitignore`: например, DLL и архивы можно добавить в Git,
но они потребуют рассмотрения и исключения для успешного статуса проверки.

Проверяется текущий снимок и снимки входящих коммитов: добавление большого
файла с последующим удалением в следующем коммите тоже обнаруживается.
При создании ветки проверяется её доступная история; ручной запуск без диапазона
проверяет только текущий снимок. Для LFS учитывается размер файла из указателя.
Содержимое архивов не распаковывается, замаскированные модели не распознаются.

## Если проверка не прошла

В Actions откройте `Repository audit`: журнал покажет путь, размер, причину и коммит.
Если файл лишний, уберите его из отслеживания и добавьте правило в `.gitignore`.
Это сохранит локальную копию:

```powershell
git rm --cached -- "путь/к/файлу"
```

`.gitignore` не удаляет файл из старых коммитов. Если файл есть во входящих
коммитах, одного нового коммита с удалением недостаточно. Для своей ещё не
слитой ветки можно подготовить чистую ветку без лишнего файла. Перезапись
общей истории требует отдельного согласования с командой.

Если файл нужен, добавьте точное исключение в `exceptions` файла `.repo-audit.json`:

```json
{
  "path": "vendor/example.dll",
  "reason": "Библиотека устройства, недоступная через NuGet; согласовано командой",
  "maxBytes": 2097152
}
```

Путь указывается от корня через `/`, без масок. Причина обязательна.
Лимит исключения ограничивает рост разрешённого файла.
Если путь также исключён `.gitignore`, добавьте там точечное правило `!`.
Правки правил, workflow и самого проверяющего скрипта должны просматриваться командой.

## Локальная проверка

Нужны Git и Node.js 22 или новее; сторонние пакеты не требуются.

```powershell
node --test scripts/repo-audit.test.mjs
node scripts/repo-audit.mjs
```

Локальный запуск проверяет закоммиченный HEAD, не неотслеживаемые файлы.
Для диапазона задайте `AUDIT_BASE` и `AUDIT_HEAD` полными SHA коммитов.

## Включение на GitHub

Файлы должны быть закоммичены и отправлены на GitHub. После первого запуска
добавьте `Repository audit` в обязательные проверки ветки `main` через
Settings → Rules → Rulesets (либо Branch protection rules).
Для этого нужны права администратора репозитория.
Проверка после push уже не может отменить загрузку: обязательный статус
останавливает слияние PR, но не служит фильтром перед отправкой Git.

## Проверка при начале чата на этом компьютере

Локальный обработчик `SessionStart` запускает `scripts/session-audit.mjs`
при начале или возобновлении чата Codex. Это не событие простого открытия окна
ChatGPT и не фоновый мониторинг при закрытом приложении.

Скрипт обновляет только ссылку `origin/main` через fetch, проверяет её историю
с последнего чистого результата и передаёт агенту отчёт. Рабочая папка,
локальные изменения и текущая ветка не переключаются. При ошибке сети явно
сообщается, что проверена только сохранённая копия. Отчёт хранится в
`.local/session-audit/report.json` и не отправляется в GitHub.

Локальное подключение обработчика должно быть подтверждено пользователем:
ChatGPT → Settings → Hooks → проверка DSP → Review/Trust.
Пока подтверждения нет, автоматический запуск не активен.
Проверка командой `node scripts/session-audit.mjs --offline` тестирует
обработчик без сети, но не доказывает, что ChatGPT уже запустил его автоматически.
