# Бэкенд чат-бота

Полная архитектура, настройка, запуск и C#-контракт: [техническая документация](TECHNICAL.md).

Наша часть предоставляет интерфейс к локальному серверу модели.
Модель не включена в проект, не скачивается и не запускается нашим кодом.
Пользователь устанавливает Ollama, LM Studio или другой сервер,
поддерживающий `GET /v1/models` и `POST /v1/chat/completions`.

## Структура

- `Backend` — C#-библиотека: `IChatBackend`, `ChatMessage`, `LocalChatBackend`.
- `Terminal` — простой клиент для ввода текста и вывода ответов.

Используется .NET 10, установленный на этом компьютере. Корневые файлы проекта
и версия .NET других компонентов не изменяются. Сторонних NuGet-зависимостей нет.
Для будущего интерфейса достаточно ссылки на `Backend/Chatbot.Backend.csproj`.

## Запуск

1. Самостоятельно запустите сервер с текстовой моделью.
2. Из корня репозитория выполните:

```powershell
dotnet run --project Chatbot/Terminal
```

3. Введите адрес API и точное название модели из выведенного списка.
4. Введите текст; терминал напечатает ответ модели.

Типовые адреса:

- LM Studio: `http://localhost:1234/v1/`.
- Ollama: `http://localhost:11434/v1/`.

В первой версии разрешены только адреса локального компьютера.
При ошибке соединения проверьте сервер и порт. Если конкретный сервер
не отдаёт список моделей, её название можно ввести вручную.

Параметры можно задать без интерактивных вопросов:

```powershell
$env:DSP_CHAT_BASE_URL = "http://localhost:1234/v1/"
$env:DSP_CHAT_MODEL = "точное-название-вашей-модели"
dotnet run --project Chatbot/Terminal
```

Если локальный сервер требует ключ, задайте `DSP_CHAT_API_KEY` в окружении.
Ключи не сохраняются в исходники или конфигурационные файлы.

Команды: `/models`, `/model <название>`, `/clear`, `/exit`.
Терминал хранит до 10 завершённых пар сообщений в оперативной памяти,
передаёт их с новым запросом и очищает при смене модели. После выхода история
не сохраняется. Ошибочный запрос не добавляется в историю. Ограничение числа
сообщений не заменяет лимит контекста модели: длинные тексты могут не поместиться.

## Подключение будущего интерфейса

Создайте `LocalChatBackend`, передав адрес сервера и при необходимости ключ.
`GetModelsAsync` возвращает идентификаторы моделей. `ReplyAsync` принимает
идентификатор модели, список `ChatMessage` и `CancellationToken`, возвращает
текст. Историей управляет вызывающий интерфейс; библиотека её не хранит.
При закрытии клиента вызовите `Dispose`. Создавать клиент на каждое сообщение не нужно.

Пока поддерживается обычный текстовый чат с полным ответом. Потоковый вывод,
действия агента, инструменты, БД, голос, память приложения и UI команды
сюда не входят.

Документация протокола:
[Ollama](https://docs.ollama.com/api/openai-compatibility),
[LM Studio](https://lmstudio.ai/docs/developer/openai-compat).
