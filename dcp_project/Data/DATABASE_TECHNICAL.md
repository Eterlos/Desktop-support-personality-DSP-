# Техническая документация --- модуль базы данных DSP

## 1. Назначение

Модуль базы данных отвечает за локальное хранение данных приложения
Desktop Support Personality (DSP) и предоставляет остальным компонентам
единый способ получать и изменять эти данные.

В текущей реализации используются SQLite и библиотека
`Microsoft.Data.Sqlite`. Доступ к базе инкапсулирован в
`DatabaseService`, структуры данных представлены отдельными моделями.

Основные задачи: - создание и инициализация базы данных; - хранение
задач и событий расписания; - хранение пользовательской памяти и
системных промптов; - хранение настроек приложения; - чтение данных для
формирования `DataBox`; - добавление, изменение и удаление записей.

## 2. Используемые технологии

  Технология                     Назначение
  ------------------------------ -----------------------------------
  C#                             Реализация слоя данных
  .NET 10                        Платформа приложения
  SQLite                         Локальная реляционная база данных
  Microsoft.Data.Sqlite 11.0.0   Подключение C# к SQLite

Пакет `Microsoft.Data.Sqlite` подключён в проекте `dcp_project`.

## 3. Структура файлов

``` text
dcp_project/
└── Data/
    ├── DataBox.cs
    ├── DatabaseService.cs
    ├── DATABASE_TECHNICAL.md
    └── Components/
        ├── UserTask.cs
        ├── ScheduleEvent.cs
        ├── UserFactMemory.cs
        └── SystemPrompt.cs
```

Назначение: - `DataBox.cs` --- общий объект, объединяющий загруженные
данные. - `DatabaseService.cs` --- инициализация базы и операции
чтения/изменения. - `UserTask.cs` --- компонента задачи и перечисление
статусов. - `ScheduleEvent.cs` --- компонента события расписания. -
`UserFactMemory.cs` --- компонента пользовательской памяти и перечисление
источников. - `SystemPrompt.cs` --- компонента системного промпта.

`DataBox` находится в пространстве имён `dcp_project.Data`, компоненты --- в
`dcp_project.Data.Components`.

## 4. Общая архитектура

``` mermaid
flowchart TD
    A[Компоненты приложения] --> B[DatabaseService]
    B --> C[(SQLite)]
    B --> D[DataBox]
    D --> E[Tasks]
    D --> F[Schedule]
    D --> G[Memory]
    D --> H[Prompts]
    D --> I[Settings]
```

Компоненты приложения обращаются к данным через `DatabaseService`, а не
выполняют SQL-запросы самостоятельно. `DataBox` --- контейнер данных; он
не выполняет запросы и не управляет сохранением.

## 5. Расположение базы данных

По умолчанию файл создаётся по пути:

``` text
%LOCALAPPDATA%\DesktopSupportPersonality\desktop_support.db
```

Каталог создаётся автоматически при создании `DatabaseService`, если его
ещё нет. При необходимости путь к файлу можно передать в конструктор ---
это удобно, например, для тестирования с временной базой.

## 6. Структура базы данных

При вызове `InitializeAsync()` создаются отсутствующие таблицы.
Используется `CREATE TABLE IF NOT EXISTS`: существующие таблицы повторно
не создаются.

### 6.1. UserTask

Хранит задачи пользователя.

  Поле                 Назначение
  -------------------- ----------------------------
  `Id`                 Идентификатор
  `Title`              Название задачи
  `OtherDescription`   Дополнительное описание
  `DeadLineAtUTC`      Срок выполнения в UTC
  `RemindAtUTC`        Время напоминания в UTC
  `Priority`           Приоритет
  `Status`             Статус
  `CreatedAtUTC`       Время создания
  `UpdatedAtUTC`       Время последнего изменения

Статус хранится строкой: `Pending`, `Done` или `Cancelled` (перечисление
`UserTaskStatus`). Для `Priority` в базе задано ограничение значений от
1 до 5.

### 6.2. ScheduleEvent

Хранит события расписания.

  Поле                  Назначение
  --------------------- --------------------------------
  `Id`                  Идентификатор
  `Title`               Название события
  `OtherDescription`    Дополнительное описание
  `StartsAtUTC`         Время начала в UTC
  `EndAtUTC`            Время окончания в UTC
  `RepeatRule`          Правило повторения
  `RemindMinutesTime`   Интервал напоминания в минутах
  `CreatedAtUTC`        Время создания
  `UpdatedAtUTC`        Время последнего изменения

`OtherDescription`, `EndAtUTC`, `RepeatRule` и `RemindMinutesTime` могут
быть пустыми (`NULL`).

### 6.3. UserFactMemory

Хранит факты пользовательской памяти.

  Поле             Назначение
  ---------------- ----------------------------
  `Id`             Идентификатор
  `Fact`           Текст факта
  `Category`       Категория
  `Source`         Источник
  `IsActive`       Признак активности
  `CreatedAtUTC`   Время создания
  `UpdatedAtUTC`   Время последнего изменения

`FactSource`: `User` --- факт добавлен пользователем; `Agent` --- факт
добавлен агентом. `IsActive` хранится как `1` (активен) или `0`
(неактивен).

### 6.4. SystemPrompt

Хранит системные промпты.

  Поле             Назначение
  ---------------- ----------------------------
  `Id`             Идентификатор
  `Title`          Название промпта
  `Text`           Текст промпта
  `Scale`          Область применения
  `SortOrder`      Порядок сортировки
  `IsActive`       Признак активности
  `CreatedAtUTC`   Время создания
  `UpdatedAtUTC`   Время последнего изменения

`Scale` --- строковое значение. `Global` может обозначать глобальный
промпт, а строка с названием модуля --- промпт для соответствующей
области. Это соглашение приложения, а не отдельное перечисление SQLite.

### 6.5. Settings

Хранит настройки в формате «ключ --- значение».

  Поле             Назначение
  ---------------- ----------------------------
  `SettingKey`     Уникальный ключ настройки
  `SettingValue`   Значение настройки
  `UpdatedAtUTC`   Время последнего изменения

Значения хранятся строками. При необходимости преобразование к `bool`,
числу или перечислению выполняет использующий настройку компонент.

## 7. Модели данных

### 7.1. DataBox

`DataBox` объединяет данные, полученные из базы: - `DateTimeLoadedAtUTC`
--- время формирования набора; - `Settings` --- словарь настроек; -
`Tasks` --- список задач; - `Schedule` --- список событий; - `Memory`
--- список фактов памяти; - `Prompts` --- список системных промптов.

Коллекции объявлены через `IReadOnlyDictionary` и `IReadOnlyList`:
потребители получают их как коллекции для чтения.

### 7.2. UserTask

Содержит идентификатор, название, описание, срок выполнения, время
напоминания, приоритет, статус и временные метки. `DeadLineAtUTC` и
`RemindAtUTC` допускают `null`.

`UserTaskStatus`: - `Pending` --- ожидает выполнения; - `Done` ---
выполнена; - `Cancelled` --- отменена.

### 7.3. ScheduleEvent

Содержит название, описание, время начала и окончания, правило
повторения, интервал напоминания и временные метки. Время начала
обязательно; время окончания и параметры повторения/напоминания могут
отсутствовать.

### 7.4. UserFactMemory

Содержит текст факта, категорию, источник, признак активности и
временные метки. `FactSource` определяет источник: `User` или `Agent`.

### 7.5. SystemPrompt

Содержит название, текст, область применения (`Scale`), порядок
сортировки, признак активности и временные метки. Наличие промпта в базе
не означает, что он уже передан языковой модели: сервис отвечает за
хранение и получение записи.

### 7.6. Связь с чат-ботом

Текущий чат использует `ChatSession` и `MemoryChatHistoryStore` из
`Chatbot/Backend`. История находится в памяти процесса и после завершения
приложения теряется. `DatabaseService` к чату пока не подключён.

`UserFactMemory` хранит отдельные факты, а не сообщения разговора.
Таблиц разговоров и сообщений в текущей схеме нет. Записи `SystemPrompt`
и `UserFactMemory` автоматически в контекст модели не попадают.
Методы чтения возвращают в том числе записи с `IsActive == false`;
будущий сборщик контекста должен самостоятельно отбирать активные записи,
учитывать область `Scale` и порядок `SortOrder` системных промптов.

Для сохранения переписки потребуется согласовать схему с владельцем БД,
реализовать адаптер `IChatHistoryStore` с атомарным добавлением пары сообщений
и восстанавливать идентификатор разговора между запусками. Кнопка очистки
чата сейчас удаляет только его историю в памяти, не факты и не промпты SQLite.

Запуск, архитектура чата и границы интеграции описаны в
[техдокументации чат-бота](../../Chatbot/TECHNICAL.md).

## 8. DatabaseService

`DatabaseService` --- основной класс взаимодействия с SQLite. Он
скрывает подключение и SQL-запросы от остальных компонентов.

### 8.1. Конструктор

``` csharp
DatabaseService(string? databasePath = null)
```

Создаёт сервис и подготавливает строку подключения. Если путь не
передан, используется расположение по умолчанию в `%LOCALAPPDATA%`. Если
передан собственный путь, используется он. Каталог создаётся при
необходимости.

### 8.2. OpenConnectionAsync

``` csharp
private Task<SqliteConnection> OpenConnectionAsync()
```

Внутренний метод сервиса: открывает соединение для его операций и не доступен
другим компонентам напрямую. Методы сервиса освобождают соединения через
`await using`; потребители используют публичные методы чтения и изменения.

### 8.3. InitializeAsync

``` csharp
Task InitializeAsync()
```

Создаёт необходимые таблицы, если они ещё не существуют. Метод следует
вызвать до операций чтения и записи. `GetStartupDataAsync()` также
выполняет инициализацию перед чтением.

### 8.4. Методы чтения

  Метод                  Результат
  ---------------------- ---------------------------
  `GetTasksAsync()`      Список задач
  `GetScheduleAsync()`   Список событий расписания
  `GetMemoryAsync()`     Список записей памяти
  `GetPromptsAsync()`    Список системных промптов
  `GetSettingsAsync()`   Словарь настроек

Методы преобразуют значения SQLite в соответствующие C#-модели.

### 8.5. GetStartupDataAsync

``` csharp
Task<DataBox> GetStartupDataAsync()
```

Инициализирует базу, получает настройки, задачи, события, память и
промпты, затем формирует `DataBox`. Это удобная точка получения полного
набора данных. Метод не запускает приложение и не подключает данные
автоматически к окнам WPF --- это делает вызывающий код.

### 8.6. Методы работы с задачами

  -----------------------------------------------------------------------
  Метод                               Назначение
  ----------------------------------- -----------------------------------
  `AddTaskAsync(UserTask task)`       Добавляет задачу и возвращает
                                      присвоенный ID

  `UpdateTaskAsync(UserTask task)`    Обновляет задачу; возвращает
                                      `true`, если запись найдена и
                                      изменена

  `DeleteTaskAsync(int id)`           Удаляет задачу по ID
  -----------------------------------------------------------------------

При добавлении ID создаётся базой. Временные метки создания/изменения
заполняются сервисом, если для новой записи они не заданы. При
обновлении передавайте актуальные значения всех полей: `null` в
nullable-полях означает очистку значения в базе.

### 8.7. Методы работы с расписанием

  ------------------------------------------------------------------------------------
  Метод                                            Назначение
  ------------------------------------------------ -----------------------------------
  `AddScheduleEventAsync(ScheduleEvent item)`      Добавляет событие и возвращает ID

  `UpdateScheduleEventAsync(ScheduleEvent item)`   Обновляет событие; возвращает
                                                   `true`, если запись найдена и
                                                   изменена

  `DeleteScheduleEventAsync(int id)`               Удаляет событие по ID
  ------------------------------------------------------------------------------------

### 8.8. Методы работы с памятью

  ------------------------------------------------------------------------------
  Метод                                      Назначение
  ------------------------------------------ -----------------------------------
  `AddMemoryAsync(UserFactMemory item)`      Добавляет факт и возвращает ID

  `UpdateMemoryAsync(UserFactMemory item)`   Обновляет факт; возвращает `true`,
                                             если запись найдена и изменена

  `DeleteMemoryAsync(int id)`                Удаляет факт по ID
  ------------------------------------------------------------------------------

### 8.9. Методы работы с промптами

  ----------------------------------------------------------------------------
  Метод                                    Назначение
  ---------------------------------------- -----------------------------------
  `AddPromptAsync(SystemPrompt item)`      Добавляет промпт и возвращает ID

  `UpdatePromptAsync(SystemPrompt item)`   Обновляет промпт; возвращает
                                           `true`, если запись найдена и
                                           изменена

  `DeletePromptAsync(int id)`              Удаляет промпт по ID
  ----------------------------------------------------------------------------

### 8.10. Методы работы с настройками

  ---------------------------------------------------------------------------------
  Метод                                         Назначение
  --------------------------------------------- -----------------------------------
  `SetSettingAsync(string key, string value)`   Добавляет настройку или обновляет
                                                её по ключу

  `DeleteSettingAsync(string key)`              Удаляет настройку по ключу
  ---------------------------------------------------------------------------------

`SetSettingAsync` использует UPSERT: существующее значение обновляется,
а при отсутствии ключа создаётся новая запись.

## 9. Примеры использования

### 9.1. Инициализация и получение данных

``` csharp
var database = new DatabaseService();

await database.InitializeAsync();

DataBox data = await database.GetStartupDataAsync();
```

### 9.2. Добавление задачи

``` csharp
var task = new UserTask
{
    Title = "Подготовить отчёт",
    OtherDescription = "Завершить раздел по базе данных",
    Priority = 1,
    Status = UserTaskStatus.Pending,
    DeadLineAtUTC = DateTime.UtcNow.AddDays(2)
};

int taskId = await database.AddTaskAsync(task);
```

### 9.3. Получение списка задач

``` csharp
IReadOnlyList<UserTask> tasks = await database.GetTasksAsync();
```

### 9.4. Сохранение настройки

``` csharp
await database.SetSettingAsync("Theme", "Dark");
```

### 9.5. Получение настроек

``` csharp
IReadOnlyDictionary<string, string> settings =
    await database.GetSettingsAsync();
```

## 10. Работа с датой и временем

Поля с суффиксом `UTC` предназначены для хранения времени в UTC. При
записи сервис приводит `DateTime` к UTC и сохраняет дату в строковом ISO
8601 формате (`O`). При чтении строка преобразуется обратно в `DateTime`
с UTC-семантикой.

Значения `DateTime` с `Kind == Unspecified` трактуются сервисом как UTC.
Поэтому вызывающий код должен передавать корректные значения времени и
не рассчитывать на автоматическое определение часового пояса для таких
дат.

## 11. Ограничения текущей реализации

1.  **Нет системы миграций схемы.** `InitializeAsync()` создаёт
    отсутствующие таблицы, но не изменяет структуру существующих. При
    изменении схемы потребуется миграция либо пересоздание тестовой
    базы.
2.  **Нет интеграции с WPF внутри `DatabaseService`.** Сервис
    предоставляет методы; вызов и отображение результатов организуют
    другие компоненты.
3.  **Нет автоматической генерации системных промптов.** Сервис хранит и
    возвращает записи `SystemPrompt`, но не формирует их содержимое.
4.  **Нет автоматического запуска напоминаний.** Сохраняются сроки и
    параметры напоминаний; обработка времени и показ уведомлений
    относятся к логике приложения.
5.  **`DataBox` формируется несколькими операциями чтения.** Метод не
    гарантирует единый снимок базы при одновременном изменении данных
    другим компонентом.
6.  **Настройки хранятся строками.** Преобразование к `bool`, числам и
    перечислениям выполняет использующий настройку код.

## 12. Рекомендации по использованию

-   Выполнять операции через `DatabaseService`, не дублируя SQL в
    компонентах приложения.
-   Использовать `await` для асинхронных методов.
-   Освобождать `SqliteConnection` после использования.
-   Для полей с суффиксом `UTC` передавать время в UTC.
-   Использовать ID, возвращённый методом добавления, если он нужен
    вызывающему компоненту.
-   При обновлении передавать полную актуальную модель: `null` в
    nullable-полях может очистить значение.
-   Не считать, что запись `SystemPrompt` уже применена языковой
    моделью: применение промптов реализуется отдельно.

## 13. Сборка и тестирование

Из корня репозитория (файла решения в текущем составе нет):

``` bash
dotnet restore dcp_project/dcp_project.csproj
dotnet build dcp_project/dcp_project.csproj
```

Запуск тестов:

``` bash
dotnet test dcp_project.Tests/dcp_project.Tests.csproj
```

Фактический результат сборки и тестирования следует указать после
выполнения команд. Наличие тестовых методов само по себе не означает,
что тесты уже успешно пройдены.

## 14. Границы ответственности

  -----------------------------------------------------------------------
  Компонент                           Ответственность
  ----------------------------------- -----------------------------------
  `DatabaseService`                   Подключение к SQLite, создание
                                      таблиц, чтение и изменение записей

  `DataBox`                           Передача набора загруженных данных
                                      между компонентами

  Компоненты `Data.Components`        Описание структуры типов данных

  UI и остальные модули               Вызов методов слоя данных,
                                      обработка и отображение информации

  LLM/чат-компонент                   Использование нужных данных и
                                      промптов при формировании
                                      контекста; интеграция не входит в
                                      обязанности `DatabaseService`
  -----------------------------------------------------------------------

понять и использовать этот компонент при интеграции.
